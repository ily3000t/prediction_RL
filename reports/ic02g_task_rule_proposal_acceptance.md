## 固定规则及拟议阈值

在运行前提交的一份规则，未因结果改变：

- 每个 task 固定 approach anchor，使用所有关键邻车共同完整的 14 ticks/2.8 秒窗；不是在线未来，也不改变原 predictor 的 25-tick 输出。
- 对每个关键 actor 先平均候选对/时间的归一化响应，再取 actor 最大值；保留所有角色、全部并列最大 actor 和数量。
- C0：I 不高于下三分位、目标前后 actor 不同且都存在、两个投影机会 gap 严格正、最大接近速度不高于训练 task 下三分位。
- C1：I 不低于上三分位、严格超过重复噪声+1e-10、关键 actor≤3。
- C0→C1→C2 优先级，其余完整任务保留 C2。并列阈值不按 ID 硬分配配额。

| 拟议边界 | 数值 | 含义 |
| --- | ---: | --- |
| I 下三分位 | 0.3976121681 | 32 个 task 的相对弱响应边界 |
| I 上三分位 | 2.6839018875 | 32 个 task 的相对强响应边界 |
| 最大目标接近速度下三分位 | 5.598775864 m/s | 相对低接近速度，不是绝对安全限值 |

这些是未批准的训练侧拟合提案，不是物理危险阈值或正式训练合同。上下边界接近的任务也不宣称具有本质不同难度。

## 需要用户选择的后续路线

1. **保留“基础控制—明确交互—完整任务”的原语义**：另提有界的任务来源覆盖方案，优先使用原生成器允许条件/训练侧来源，不直接改背景行为或预测器。先明确规模、预算、入口和 predictor 覆盖，再取得采集授权；扩池不保证一定达到 C0=10，不能按策略输赢挑场景。
2. **将研究明确改为“弱交互—明确交互—完整任务”的交互强度课程**：另建规则版本，D 作为独立报告与匹配分析，首层不再宣称低控制难度。这是研究定义变化，应明确批准，不把放宽 C0 条件包装为原初稿通过。原报告保留，正式评价仍沿用被冻结开发方案。

本阶段不自动选择任一路线，不降低每层覆盖要求，不扩大模型，不补采，不开始调度/训练。先确定课程的第一层究竟要证明“低控制难度”，还是“弱动作条件交互”；确认后再开展下一项原子开发。
