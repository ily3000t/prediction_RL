# IC02c：训练任务参考刻画与有限覆盖提案

## 决策与现有缺口

本阶段只实现离线设计审计。`configs/development/ic02c_task_design_v1.json` 是不可执行提案，不是采集或训练授权。它不能通过修改布尔字段变成运行请求。

713 个旧 root 来自 256 个训练侧 episode，全部在参考控制后的第 32–137 个控制步，没有原 reset 时刻的候选未来。旧规则得到 C0=0、C1=211、C2=502；结果和阈值保持原样。IC02b 的三个真实 reset 样本提供起步观测，但没有候选分支，不能据此计算邻车响应 I、宣布低交互或估计目标分布 pi。

因此先补任务入口及早期匝道的参考刻画，不增加预测网络、不扩训练预算，也不把“有 C1 root”变成“C1 task”。初始剩余合流距离在已有三个样本中均约 214.10 m，与旧近合流 root 的位置分布不同，不直接套用旧 root 分位数。

## 冻结对象与检查点提案

任务仍为 `seeded_fresh_gym20_task_v1`：原生成器配置、显式训练 seed、first episode、原 Gym20 reset、原插入位置和起步采样。真实训练时 DDPG 从 reset 的首个 observation 接管，**不执行参考前缀**。

参考控制只用于离线刻画，复用旧数据采集所用作者 DDPG 的 greedy/TimeFeature 接口与权重。不以 B2/B3 的胜负、碰撞率或回报挑选任务。

| 检查点 | 触发定义 | 目的 |
| --- | --- | --- |
| reset | 原首个非终止 reset 状态，控制步 0 | 核查启动控制与初始交互 |
| early_ramp | 第一次非终止跨过 ramp_0 的 80 m 位置 | 覆盖早期匝道 |
| approach | 第一次非终止进入 ramp_0 距终点 20 m 内 | 对接旧近合流刻画 |

每条参考发现轨迹最多 128 控制步；天然终止或未到达的检查点明确保留为 unavailable，不换 seed、不自动补采、不把缺失 I 写成零。位置触发是提案定义，并非已验证的最佳分层检查点。

候选沿用五个 jerk `[-5, -2.5, 0, 2.5, 5]`，作用一个原控制周期，再按原零 jerk 后续规则推进，最多 25 步/5 s。每个候选做两次独立恢复，检验重复噪声和分支顺序；对齐稳定车辆 ID、公共道路坐标与共同有效时间，不能把 ego 几何差异计入邻车 I。保留当前 critical-role、邻车容量 12（ego 单独编码，不占邻车槽位）、history 上限 11 和原 mask；reset 仅有 1 帧，不免费补历史。

现有 `geometric_roots` 不允许同一车道的多个检查点，不能把本提案直接传给旧采集 CLI。后续需要独立检查点 observer，不能改共享扫描器以静默改变旧数据语义。仍用已验证的 fresh SUMO prefix replay，不假设原生 snapshot 恢复已获验收。

## 任务选择与有限预算

来源是完整训练 roster 11000–11255。固定步长 8 提案得到 32 个 seed：11000、11008、…、11248；不读取评价结果选择。这是覆盖 pilot，不是随机代表性估计，也不是最终课程池或 pi。

先提议 11000/11008/11016 三任务工程阶段，验收后另请批准剩余 29 个；32-task 总量包括已完成的三任务，只有完全一致的来源、协议和完整 receipt 才能复用，否则停止审查，不能自动重跑。

每个 task 最多：两次参考发现、三个检查点各两次 root 捕获、各十次候选分叉。各次捕获/分叉均重启 SUMO 并重放原参考前缀，不能只计算未来 25 步。

| 预算上限 | 三任务工程提案 | 32 任务 pilot 总提案 |
| --- | ---: | ---: |
| 独立训练侧任务 | 3 | 32 |
| reference root 槽位 | 9 | 96 |
| 候选分叉执行 | 90 | 960 |
| 新 SUMO 会话 | 114 | 1,216 |
| 参考发现控制步 | 768 | 8,192 |
| root 捕获前缀控制步 | 1,536 | 16,384 |
| 候选恢复前缀控制步 | 7,680 | 81,920 |
| 候选未来控制步 | 2,250 | 24,000 |
| 总控制步 | 12,234 | 130,496 |
| 预热及插入 tick | 11,514 | 122,816 |
| cleanup tick 上限 | 114 | 1,216 |
| 总 raw tick 上限 | 23,862 | 254,528 |

raw tick 上限含每会话原 100+1 等待/插入 tick 和最多一个 cleanup tick；不是 wall-clock 预测。参考模型调用最多等于发现控制步；重放固定动作前缀不重新调用策略。冻结普通/条件预测器推理、预测器训练、learner transition、DDPG 更新均为零。

## 任务分层尚未冻结

未来采集应保留每检查点 D 向量、关键车辆、I 的有效支持、重复噪声、actor/history 覆盖及不可达原因，再提出 task 聚合规则。可讨论合格检查点的 I 最大值，但不能直接用“任一 root 为 C1”命名整条任务。C0 的低 I 必须有足够共同未来支持；空关键集合、历史不足、终止删失不自动等于零响应。

本阶段不冻结新的 D/I 数值阈值、task classifier 或 pi。旧 IC01 的 root 阈值不变；新任务规则属于新单位，不是把旧失败改成通过。若 C1 极少、I 主要来自坐标误差或 C0 仍缺失，保留结果并暂停课程训练。

## 后续工程验收与边界

只有用户明确批准命名协议与三任务预算后，才实现并执行独立 collector。先用离线 fixture 检查：同 seed/动作恢复一致、同车道多检查点、reset 单帧 mask、分支无污染、真实终止与 cap 区分、非法/缺失输入拒绝、预算上限及 receipt 绑定。

新 live collector 应在比较前后及失败路径记录所需文件/RNG postflight；不能用新运行补造 IC02b 原进程缺失的最终内存检查。开始但不完整的任务不自动重跑；失败也保留、正常汇总。候选未来仅用于离线层描述，禁止进入在线 observation、reward、动作或 teacher。

三任务工程阶段、32-task 覆盖 pilot、任务分层冻结、持久 learner/replay 接入和完整课程训练是不同批准点。当前 `runtime_authorized=false`、`training_ready=false`，没有课程训练命令，不合并 main、不推送、不打课程运行标签。
