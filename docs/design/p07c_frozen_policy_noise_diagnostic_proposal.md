# P7c 固定策略探索噪声诊断草案

状态：DRAFT，未实现 CLI、未冻结可执行配置、未启动仿真或训练。
前置：完整 P7 与 P7b 已核验；结果见 reports/p07b_results_review_20261001.md。
需要用户确认本诊断方向后再实现和测试；不能将本文件当成启动命令。

## 唯一问题与保持不变的内容

在相同现有 checkpoint、同一开发交通场景下，仅加入原 DDPG 训练探索
分布的动作噪声，会不会解除或加剧已有停滞/碰撞？
这不是新方法效果实验，也不完整隔离训练交通分布变化。

保持 B0/B1/B2/B3、全部训练种子 0/1/2、开发场景 200/210/219、现有预测器、
原奖励、连续 jerk、原 SUMO 设置和 simulation_blocking_exact_v1。
不训练，不改 replay，不更新 actor/critic，不加入 ST、Shield、commitment、
动作候选吸附、速度下限或按场景切换预测器。
不得调用训练 act() 来模拟噪声，因为它会存储 replay 和尝试优化器更新。

## 拟冻结条件

- deterministic：复用 P7b 的 36 个完整确定性记录，校验收据与精确 P7 绑定。
- upstream_noise：同样 36 个 checkpoint/场景单元，预先固定三个噪声重复
  seed 0/1/2，共 108 个新回合，最多 54,000 步，用户运行。
- 不增加新交通 seeds，不从表现中筛选策略；三个噪声重复不是三个新场景。

已检查本地 ALL 0.5.3 实现：原训练噪声为零均值高斯，标准差
noise × (high-low)/2 = 0.1 × 5 = 0.5 m/s^3，加入 actor 输出后裁剪到 [-5,5]。
实现必须核验与安装库和已记录 preset 的一致性，不凭本文数值静默重写规则。
诊断明确使用同样的噪声分布，但不声称复现原训练时未知的逐步噪声序列。

使用独立的、显式绑定的 CPU Torch generator。相同 scene/repeat 的噪声序列
在所有方法/训练种子之间使用共同前缀；不能以方法名或训练种子选择噪声。
该 generator 不推进 SUMO/NumPy/Python/全局 Torch RNG；动作改变后的交通响应
允许自然不同。保存原 actor 动作、噪声、裁剪前/后请求与实际执行审计。

## 实现与工程验收要求

1. 新模块和新请求独立绑定历史 P7/P7b；不改旧源码、哈希、报告或配置。
2. 噪声关闭的旁路必须逐动作/奖励/结果回归既有记录；噪声打开不能要求
   动作轨迹仍等于确定性原结果。起始交通必须匹配，其他冻结语义不变。
3. 各独立重复可重放；共享前缀、裁剪、RNG 隔离、时间通道与终止处理有测试。
4. 所有网络、optimizer、replay 保持冻结；异常结果不能变成普通驾驶失败。
5. 负效果也完整聚合；不可根据是否前进、是否更安全删重复或改变噪声幅度。
6. 新输出短 run ID、不可覆盖、complete-only resume；有上限 smoke 后再准备
   用户运行请求。完整 108 个新回合不由开发助手自动执行。

## 统计与解释

先对同 checkpoint/scene 的三个噪声重复平均，再与原确定性结果直接配对，
随后逐训练种子平均场景，最后等权报告三个训练种子。
报告原回报、到达、碰撞、仿真时间上限、低速/进度和控制代价；保留完整分母。
只有三个开发交通场景，重复和时间步不冒充独立交通样本，不报未预定 p 值。

若噪声帮助解除停滞：支持存在探索/确定性执行差异，不证明预测器已经有效，
也不允许将正式评价改成有噪声以“修成通过”。
若噪声无帮助或增大碰撞：保留负结果，再考虑训练预算、特征利用与数据覆盖，
不自动增加模型、改奖励或换 seed。

本草案不批准 P8、正式训练、数据重收集、测试集开放或部署 runtime。
